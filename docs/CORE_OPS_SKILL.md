# 新分支核心运营思路 v0.4.0

核心数据分析统一入口，与王焓直播复盘0.4.1共用融合流程。

流程：目标/模块初判→录屏与数据证据→说话人核验→时间轴对齐→节点与漏斗→战略与运营部门审查→实验→台账。

当前首要目标：提高进房与新人留存。主指标为同来源曝光进房率，新人60秒留存是共同成功条件。不能只看进房或流水上涨。

调用：

```text
使用 $wanghan-core-ops 的核心数据分析功能，提高进房与新人留存。
直播日期：[日期]
资料：[B站链接/可信转写与抖音后台数据]
先归类模块和功能，再给可信时间轴、漏斗瓶颈、证据等级、运营部门审查与下一轮实验。
```

[Skill入口](../skills/wanghan-core-ops/SKILL.md) · [统一分析模板](../skills/wanghan-core-ops/references/core-data-analysis.md) · [内置复盘方法](../skills/wanghan-core-ops/references/live-review-method.md)

八大战略模块、默认优先级和不主动写话术的边界保留。两个插件均可单独调用，内置相同方法；同时调用共用一个任务，只采集和转写一次，输出一份报告。包是可复用分析说明，实际采集和转写工具仍须核验；缺数据就标明缺口，不宣称效果已验证。

`skills/wanghan-core-ops/SKILL.md` 是统一入口；references中分别维护运营部门审查、指标、复盘方法、时间轴和统一报告。
插件身份、中文展示名和现有提示保持；核心版本0.4.0、直播复盘版本0.4.1。原王焓直播复盘入口继续保留。
包是单一顶层wanghan-core-ops目录，包含plugin.json、.codex-plugin/plugin.json、README.md和完整skills目录。无需新MCP服务器；实际工具可用性须逐次核验。
真实达成进房/留存目标需要可比实测数据。源码与示例只描述方法，不宣称流量提升。公开仓库不存私人后台明细或身份信息。

## v0.4.0 融合流程

[融合协议](../skills/wanghan-core-ops/references/fusion-workflow.md)统一两个入口的资料去重、转写与身份独立审查、时间轴校准、五层漏斗、八模块战略判断和下一轮实验。[王焓直播复盘入口](../skills/wanghan-live-review/SKILL.md)内置同一套方法，不依赖另一个插件是否安装。

两个入口同时被调用时，复用同一场次与参数下已审查的结果；completed标签不能代替质量审查。主说话簇只作候选，不能直接确认王焓。非粉丝不能代替新人，缺少新人60秒留存时只标待补数。
