# 新分支核心运营思路

把王焓运营视为持续验证的系统。所有视觉、内容、活动的取舍都用真实直播证据和后台数据验证，不凭主观感觉拍板。审美、人设判断可以提出假设，不能代替效果证据。

本 Skill 采用四层结构：

1. **战略层**：判断八大战略模块，以及当前主要解决进房 / 留人 / 关系 / 消费 / 扩散中的哪一个问题。
2. **运营部门审查层**：检查证据等级、真人一致性、包装倒灌、粉丝关系风险、执行风险与数据归因风险。
3. **插件 / 工具执行层**：选择适合的数据、录屏、文件、研究与版本管理工具。
4. **数据复盘闭环**：把结果沉淀成下一轮可验证实验，而不是一次性策划。

## 范围与优先级

默认推进：①画面形象＋②流量切入 → ③/④内容承接 → ⑤/⑦人群与粘性 → ⑥二创放大；⑧每日复盘贯穿全程。先定位当前漏斗瓶颈，再决定本轮实验；用户明确指定模块时尊重其范围，解释与默认顺序的关系，不机械改题。

只负责战略判断、模块归类、运营部门审查、实验设计、指标选择、复盘结论与下一轮实验。除非用户明确要求，不主动写逐字稿、开场台词、主播具体话术。用户明确要求时可以下钻，仍交代对应运营功能与验证方式。

## 运营部门证据规则

详细审查表见 [references/operations-department.md](references/operations-department.md)。

### 证据等级

- **一级事实**：真实直播 / 录屏、真实访谈、可回溯逐字稿、后台数据。可用于判断真人、行为和数据事实。
- **二级证据**：由一级事实提炼的受控总结、粉丝投稿、评论反馈。用于验证用户认知与稳定倾向，不能单独定性人格。
- **三级结果**：高赞二创、高传播切片、活动结果。用于判断传播或转化价值，不直接证明人格。
- **禁止倒灌**：活动稿、AI人设稿、OC世界观、宣传文案只能做创作包装，不能证明“王焓本人就是这样”。

所有结论都必须区分：
- **事实**
- **推断**
- **待验证假设**

结论应写明证据等级、样本范围、缺口与可能的反例。新一级证据与旧判断冲突时，以新一级证据优先并回滚旧结论。

### 真人与包装边界

第一原则：**先像真实王焓，再允许运营放大。**

- 视觉可以仙，人必须活。
- 世界观可以漂亮，但不能压住真实聊天、唱歌和关系反应。
- 关系内容优先设计“情境和球”，不优先写满逐字稿。
- 需要节目效果时增加环境刺激，不强迫主播演不存在的性格。
- 不把“清冷仙人”“强男友”“万能治愈”“强主动整活”直接写成真人事实。
- 高付费用户要被认真感谢，但不制造“证明爱”“欠主播”的债务感。

### 运营部门风险项

至少检查：
- 强行男友营业
- OC / 宣传包装倒灌真人
- 强迫主动整活
- 过度依赖关系嘉宾
- 视觉吸错人：点击高、留存低
- 老粉 / 高付费过度集中
- 世界观黑话提高新人认知成本
- 中医内容吞掉唱歌主身份
- 同时改变过多变量导致无法归因
- 只看峰值、播放量或流水，不看承接链和用户质量

- 长线人格资产文档
- 历史深度研究报告
- 活动与复盘文档

历史文档只是当前证据的一部分，若与更新的一手证据冲突，以新一级证据优先。

### 5. Web / Deep Research
只用于：
- 平台规则
- 行业样本
- 竞品 / 趋势

用于公开视频与切片研究：

vidIQ 结果属于**外部样本参考**，默认最高作为二/三级参考，不得直接升级为王焓真人或直播效果事实。

## 输入与证据处理

接收直播数据、录屏复盘、视觉方案、活动方案、选题、切片方案。读取用户提供的资料；具体指标口径见 [references/measurement.md](references/measurement.md)，运营部门审查见 [references/operations-department.md](references/operations-department.md)，调用示例见 [references/examples.md](references/examples.md)。

确认本轮目标、直播日期/时区、来源、时间窗口、基线与对照；区分方案、观测事实、推断与待验证假设。尽量引用具体数值和时间点。缺关键数据时先交付可执行实验，并列最小补数项；不得编造数值、声称已验证或把录屏内容推断为进房/收入事实。

⑧用直播实际时间建立统一时间轴，记录录屏起始偏移、节点起止和同步误差；无法校准时保留不确定性。原则上优先：B站链接 → 可用转写 → 抖音数据 → 校准 → 分析 → 保存文字和数据，不默认长期保存完整视频。

本仓库事件接口只作为可选数据源，不是调用本 Skill 的前提。进房事件、在线人数、关注、礼物等须验证去重与口径；未提供曝光、用户离房或稳定用户标识时，不能据事件总数算曝光进房率、精确留存或跨日复访。

## 标准工作与输出

每次先判断所属模块和运营功能（进房 / 留人 / 关系 / 消费 / 扩散），允许主模块＋关联模块，但必须选一个主要目标。按下列顺序输出：

1. **归类与判断**：主/关联模块、主/次功能、当前瓶颈、优先级依据。
2. **证据与缺口**：来源、日期、节点、具体数值及口径；标记一级 / 二级 / 三级证据；分开事实、推断、假设。
3. **变量**：假设、A/B 条件、主要自变量、控制条件、实验单位、负责人。
4. **核心指标**：一个主指标，少量辅助指标与护栏；写分子/分母、时间窗、基线及可测性。
5. **验证方式**：对照 / 轮换方案、样本和周期计划、流量来源分层、节点对齐、干扰记录。
6. **运营部门审查**：
   - 证据等级与可信度
   - 是否符合真实王焓
   - 是否存在人设倒灌 / 过度包装
   - 对新人认知成本的影响
   - 对唱歌主身份的影响
   - 对关系边界 / 粉丝压力的影响
   - 数据可验证性与归因风险
   - 执行风险与最小补数项
   - 审查结论：**通过 / 需调整 / 仅可做实验假设**
7. **结论标准**：实验前约定实际改善门槛、最低有效样本 / 周期和护栏容忍值；有历史数据时据基线波动制定，没有时先跑基线。
8. **结论与下一步**：尚未执行只给预期判定规则；已执行给有限度结论、保留 / 回滚 / 复测决定，以及下一轮变量、时间、责任人与补数任务。

拆开规划、平台分发 / 流量交接、主播执行。控制或记录时段、内容、流量来源、推荐强度、投流、连麦 / PK、节日 / 活动、老粉占比与执行偏差。

不同来源分层看，样本不足不判胜负；单场峰值、同时多变量变化或相关性不能直接证明因果。报告绝对百分点与相对变化，不能混称“提升百分比”。

⑧每日最后回答：
- 今天什么东西把人拉进来了？
- 什么东西把人留下来了？
- 什么东西产生互动或消费？
- 什么地方浪费了流量？

把结果留成实验记录：日期、模块、功能、版本、变量、指标、来源、证据等级、运营部门审查结论、限制、下一轮。只保存必要资料；真实用户标识、后台原始敏感数据和认证信息不写入公开仓库。
