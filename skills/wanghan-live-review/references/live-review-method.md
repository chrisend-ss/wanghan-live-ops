# 内置直播复盘方法

来源：用户选定的 wanghan-live-review 0.4.0，整合于 wanghan-core-ops 0.4.0；与王焓直播复盘0.4.1共用融合协议。以下方法用于证据链；最终只交付 core-data-analysis.md 定义的统一报告。

## 执行前门槛与优先规则

- 先检查会话可用工具、仓库当前实现、任务状态和输出完整性；插件包含说明，不代表自带转写服务。缺能力时交付可完成的部分及具体缺口。
- 同BV/分P/输入版本/模型参数已有有效精准结果则复用；completed 还须核对覆盖时长、质量报告、音频分区、说话人置信度。失败或仅部分覆盖不得当完整结果。
- 自动ASR与聚类标签均为待核验草稿，speaker=王焓不是身份确认。没有同录像内已确认参考段时只保留主cluster候选，身份视为未确认，不能强定真人性格或习惯。采集与验收优先按source-acquisition.md执行。
- 日期与分P取用户说明或来源元数据，不凭BV编号猜测；请求中不放敏感标识或认证信息。
- 文中事件清单是分析层候选；适配器/API支持哪些字段必须查当前schema，不向不支持的API投递share/marker/speech/music。缺曝光、离房或稳定用户标识时相应比率/留存/复访不可计算。
- 文中云端流程只有实际可用时执行。新任务须在原授权范围内；公开仓库不保存私人后台和可识别用户资料，原始媒体不长期保留。提交任务后报告运行中，不创建后台监控承诺；只有用户要求时设置后续提醒。
- 时间校准与证据强度按 core-data-analysis.md；数据同步不等于因果。


# 王焓直播复盘

这是王焓抖音娱乐直播的专用复盘技能。核心任务不是“把录屏转成一大段字”，而是建立可信时间轴：

**王焓真正说了什么 / 其他人说了什么 / 哪些只是背景音乐或歌唱**
→ **直播间此时发生了什么**
→ **进人—留人—互动—转粉—付费是否发生变化**。

## 总原则

1. 用户是运营，王焓是主播。输出服务运营决策。
2. 直接接收 B站 URL/BV；不要求用户先下载完整视频。
3. 优先低存储：临时媒体只存在于云端 Runner，长期保存文字、时间码、事件和报告。
4. 不把所有检测到的声音都写成“王焓”。说话人无法确认时必须标低置信度或“未知”。
5. 背景音乐、歌曲、环境声不能当王焓口播写入主播语料库。
6. 自动识别是证据草稿，不是人工校对全文。
7. 相关性不等于因果；内容节点与数据变化必须区分证据强度。

# 一、B站精准转写 V2（默认优先）

当用户直接给 B站录屏链接并要求复盘，优先使用 `chrisend-ss/wanghan-live-ops` 的 precision pipeline，而不是旧版“整轨 Whisper + 全部标王焓”。

## 精准链路

1. Chromium/页面媒体接口获取 B站实际音轨；公开视频字幕只作辅助，不作为精准模式主证据。
2. 把音频统一转为 16kHz 单声道 PCM WAV。
3. 用 `inaSpeechSegmenter` 先做**说话 / 音乐歌唱 / 噪声**分段。
   - speech 才进入 ASR；
   - music/singing 标为 `背景音乐/歌唱`，默认不送入文字识别；
   - noise/noEnergy 标为环境声；
   - 这样避免把歌词、BGM、音乐人声误写成王焓口播。
4. 对 speech 段使用 `faster-whisper` 高精度参数：
   - 精准模式优先 `large-v3`；
   - beam search；
   - `condition_on_previous_text=false` 减少跨段幻觉；
   - 使用王焓项目热词：王焓、焓太医、听潮阁、中医、连麦、PK、粉丝团、灯牌、音浪、开灯等；
   - 使用 `avg_logprob` 与 `no_speech_prob` 做保守过滤。
5. 对 speech 段使用 SpeechBrain ECAPA speaker embedding 做多人说话人聚类。
6. 王焓身份识别优先级：
   - **High模型标签**：同一录像中给出已确认的王焓纯说话时间段作为reference，再匹配；仍须独立检查参考纯净度和ASR质量，不自动等于身份确认；
   - **Medium旧标签**：没有reference时，时长与出现次序只能产生主cluster候选，身份标未确认，不纳入王焓确认语料；
   - **Low**：短句/混音严重/无法稳定归类，标 `说话人_未知`，不得强行写王焓。
7. 不默认长期保存王焓声纹向量。持续声纹档案属于更敏感的生物特征型数据，只有用户明确要求后才考虑持久化；默认只使用**同一录像内的参考时间段**。

## 精准模式请求字段

GitHub `review_requests/*.json` 可包含：

- `precision_mode: true`
- `model: "large-v3"`
- `hotwords: "..."`
- `wanghan_reference_ranges: [[start_sec, end_sec], ...]`
- `output_suffix: "precise_v2"`

若没有reference，可运行聚类和转写，但王焓身份仍未确认；保留原始标签用于审计，不将主cluster升级为王焓原话。

## 精准输出

优先读取：

- `reviews/<date>_<bvid>_<suffix>/status.json`
- `metadata.json`
- `transcript.jsonl`
- `transcript.md`
- `quality_report.json`
- `audio_zones.jsonl`

`transcript.jsonl` 的关键字段包括：

- `start_seconds`
- `end_seconds`
- `kind`: speech / music / noise
- `speaker`: 王焓 / 其他说话人_N / 说话人_未知 / 背景音乐/歌唱
- `speaker_confidence`: high / medium / low
- `speaker_cluster`
- `text`
- `avg_logprob`
- `no_speech_prob`

复盘王焓本人表达时，默认只纳入：

- `kind == speech`
- `speaker == 王焓`
- 已核验参考和身份；ASR质量独立通过或原音已人工确认。旧high/medium或主cluster标签不能单独作为纳入条件。

背景音乐/歌唱只作为节目节点，不进入王焓口头禅、表达习惯、话术风格样本。

# 二、旧版转写的处理

旧数据若来源为普通 Whisper 或 B站字幕，并且 speaker 被统一写成王焓：

- 不再把这个 speaker 标签视为可信；
- 需要分析说话习惯时，优先重新跑 precision mode；
- 无法重跑时，把文本视为“未分说话人转写”，不能直接归入王焓语料。

# 三、B站低存储云端流程

当用户提供 B站 URL/BV：

1. 提取 BV 与日期。
2. 先查已有精准结果；若已 completed 直接复用。
3. 没有精准结果时，创建/更新 `review_requests`，默认开 precision mode。
4. GitHub Actions 负责临时下载音频、分段、识别、说话人聚类。
5. Runner 结束后临时媒体销毁；仓库只保留文字与结构化元数据。
6. workflow artifact 已生成但 commit 冲突时，先从 artifact 继续复盘，不把 commit 冲突误判成转写失败。

# 四、直播事件统一结构

标准事件：

- `enter` 进房
- `chat` 弹幕
- `like` 点赞
- `follow` 关注
- `gift` 礼物
- `fanclub` 粉丝团
- `share` 分享
- `audience_stats` 在线/累计观看
- `marker` 运营节点
- `speech` 王焓/其他人讲话
- `music` 背景音乐/唱歌
- `system` 其他系统事件

第三方采集器只通过 adapter 接入统一 schema；不要把逆向采集源码直接绑死到复盘层。

# 五、时间轴校准

录像与抖音事件必须先校准。优先共同锚点：

- 开灯；
- 某首歌开始；
- PK开始；
- 明确礼物大峰值后的主播回应；
- 某句能在弹幕与录屏同时定位的话。

若偏移不稳定，用分段 offset，不要全场硬套一个值。

# 六、五层运营漏斗

## 进人
看曝光、进房、进入率、进房速度、流量来源。

## 留人
看30秒/1分钟留存、平均停留、在线、节点后承接。

## 互动
看弹幕、点赞、分享、互动用户、主播回应。

## 转粉/关系
看关注、粉丝团、场后粉丝增量、新老用户结构。

## 付费
看礼物次数、付费人数、付费率、人均付费、峰值与内容节点。

# 七、内容节点分类

- opening 开场
- chatting 聊天
- singing 唱歌
- medical_topic 中医/知识
- call 连麦
- pk PK
- game 游戏
- story/worldview 剧情/世界观
- ceremony 仪式
- conversion 关注/粉丝团/礼物转化
- transition 转场/找歌/技术等待
- silence 空档

注意：`singing` 是直播内容类型；音频识别层可同时把其音频分类为 music/singing，避免误入“王焓说话语料”。

# 八、视觉/换皮/发色实验

分析银白、黑发、玫红等视觉版本时：

- 不用不同场次的流水差异直接证明发色因果；
- 第一阶段固定背景、服装、构图、时段、内容，只换发色；
- 第二阶段再比较完整视觉套装；
- 重点看进入率、30秒/1分钟留存、平均停留、关注、粉丝团、付费。

# 九、默认复盘输出

1. 一句话结论；
2. 数据/转写可信度审计；
3. 关键节点表；
4. 进人、留人、互动、转粉、付费五条链路；
5. 王焓本人内容表现（只用可信 speaker 段）；
6. 其他说话人、BGM、歌曲对节奏的影响；
7. 流量断层与高峰浪费；
8. 下一场最值得改的 3 件事；
9. 证据缺口和需验证假设。

# 十、质量要求

- 王焓原话与助手概括严格分开；
- 不把音乐歌词当口播；
- 不把嘉宾/连麦对象的话当王焓；
- 低置信度片段不能用来总结王焓固定说话习惯；
- 后台指标写清口径；
- 截图或整场汇总数据不能伪装成分钟级曲线；
- 单个峰值不等于因果；
- 结论必须落到可执行运营动作。
