# 核心数据分析：统一报告与目标实验

## 目标与范围

用可信内容解释实际数据变化，再用八模块决定下一步。对已指定的“提高进房与新人留存”，主模块①/②，关联④/⑧；进房率和新人60秒留存共同决定采用，不用流水代替。

策略、复盘和切片并非同一个问题。核心数据分析可对齐后台判断直播效果；用户仅要求切片时，按既定约定只依据B站内容判断剪辑素材，不用抖音流量替代内容价值。

没有实测数据时的当前判定是“未执行/证据不足”。目标计划不是已经实现的增长。真实达成需在预设样本、时间窗、流量分层和护栏条件下重复验证。

## 数据交接与校准

先建立场次卡：session_id、实际直播日期、时区、BV/分P、转写处理日期、原始来源、覆盖时长、visual_variant、数据粒度及可用字段。处理日期不等于直播日期，视频标题仅是候选日期证据。

四个可信度分开：来源证据等级、speaker_confidence、transcript_confidence、alignment_confidence。即使speaker high也不能证明ASR文字正确。没有ASR可信字段或人工复核时标未核验；说话人簇数量明显异常时不把簇数当真实人数。原话保留原文，摘要分列。

时间轴字段参考 [live-review-schema.md](live-review-schema.md)。录屏时间先保留；实际时间按以下关系记录：

`live_time = recording_start_live_time + video_seconds + segment_offset_seconds`

至少两个能在两侧独立定位的锚点用于检验偏移/漂移，如开灯、明确歌曲开始、PK开始、礼物回应。一个锚点只给暂定偏移；没有两侧锚点，actual live_time、offset、error标未知。ASR报时只能作候选，不单独认定真实开播时间。录像00:00不默认是直播开场。存在剪辑、暂停或分P时用分段校准，报告残差和不可校准区间。

同一窗口对齐内容起止、视觉变化、曝光/进房、在线、弹幕、关注、粉丝团、付费。窗口长度据后台粒度预先确定；粗采样不插值成精细观测。区分窗口新增量、累计量与瞬时在线，累计值先求差且处理重置；不重复统计平台已有去重人数。

## 一份统一交付

1. **结论与归类**：本轮目标、主/关联模块、功能、瓶颈、结论强度和任务完成状态。
2. **证据卡**：场次/覆盖/来源、数值与口径、四项可信度、缺失项。
3. **关键节点表**：录屏起止、校准实际时间、内容/视觉、五层指标、同期干扰、事实/推断、证据定位。缺数据填NA与原因。
4. **五层漏斗**：进房→留人→互动→关注/关系→付费；扩散单独检查真实归因。只在可测范围计算。
5. **运营部门审查**：沿用operations-department.md，检查真人一致性、包装倒灌、唱歌主身份、关系和执行风险，给通过/需调整/仅可做实验假设。
6. **下一轮实验**：变量、主指标、留存条件、辅助/护栏、可比对照、样本与周期、改善门槛、停止规则、责任/时间、补数项。按measurement.md写分母，不使用通用必胜阈值。
7. **行动与台账**：下一场最值得做的最多3件事，写预期机制与如何验证；若只够1件就只写1件。更新实验台账，不虚构执行完成。

日复盘四问：什么拉人、什么留人、什么促互动/消费、哪里浪费流量。无对应数据的回答只能是待验证假设。

## 首轮：进房与新人留存

优先跑基线后选一个主要变量，不能同场把发色、背景、开场、嘉宾与内容全部换掉。

| 阶段 | 决策与实验 | 验证 |
|---|---|---|
| 基线 | 同来源、同口径可比场次；梳理开灯/首唱/转场等节点 | 曝光、进房、新人60秒留存、关注及混杂；未知字段先补 |
| ①视觉 | 固定背景/服装/构图/开场，只换一项发色或明暗 | 进房率主指标＋新人留存共同条件 |
| ②切入 | 固定画面/主题/时段，比较一个开场结构或节点顺序 | 同来源进房率，及入房队列60秒留存 |
| ④承接 | 当进房上升但留存下降时，测试新人首分钟内容承接 | 此轮留存可作为主指标，进房保持护栏 |

事前约定：相对基线至少改善多少、样本/重复周期够不够、留存最大容忍跌幅、来源结构可比性；无历史数据先观测，不编百分比承诺。平衡A/B顺序、记录执行偏差；没有随机化就注明准实验限制。
